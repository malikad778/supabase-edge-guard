Rule Catalog

Built-In Heuristic Rules (SG001 - SG018)

Every rule is designed to prefer false negatives over false positives, keeping your CI builds signal-rich and trustworthy.

SG001 error · ts
ServerAuthGetSessionSpoof

getSession() reads the cookie without cryptographic verification. Malicious callers can forge JWT claims to authenticate as any user.

SG002 error · ts
ServiceRoleWithoutAuthCheck

A service_role client completely bypasses Row Level Security. Passing user input to it without prior auth verification exposes all data.

SG003 error · cross
ServiceRoleInClientBundle

A service_role key referenced in a module reachable by the client bundle graph. Anyone can extract the key from browser JS.

SG004 error · cross
SecurityDefinerRpcExposed

Browser calls supabase.rpc() on a SECURITY DEFINER function that is granted to anon/public and never checks auth.uid().

SG005 warning · sql
RlsPolicyAuthUidNotWrapped

Calling auth.uid() directly forces Postgres to re-evaluate auth for every candidate row. Wrapping in (select auth.uid()) computes it once.

SG010 error · sql
TableWithoutRls

A table created in an exposed schema without ENABLE ROW LEVEL SECURITY allows anyone with the anon key full read and write access.

Ecosystem

Zero-Config CI & MCP Integrations

Run on pull requests, pre-commit hooks, or directly inside your AI IDE.

GitHub Action (SARIF + Sticky PR)

Runs on pull requests, uploads SARIF to the Security alerts tab, and keeps a single updated sticky PR comment.

# .github/workflows/edge-guard.yml
name: Security Audit
on: [pull_request]
permissions:
  contents: read
  security-events: write
  pull-requests: write
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: malikad778/supabase-edge-guard@v0
        with:
          fail-on: error
          upload-sarif: 'true'
          comment: 'true'
