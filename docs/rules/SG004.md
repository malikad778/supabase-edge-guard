# SG004 - SecurityDefinerRpcExposed

**Severity:** error · **Layer:** cross · **Auto-fix:** safe

> supabase.rpc() calls a SECURITY DEFINER function that is callable by anon/public and does not check auth.uid().

## Why it matters

SECURITY DEFINER functions run with the owner's privileges and therefore bypass RLS. PostgREST exposes every function in an exposed schema as /rpc/<name>, and Postgres grants EXECUTE to PUBLIC by default. Unless the body checks auth.uid() or EXECUTE is revoked, anyone with the anon key can call it.

## Bad

```sql
create function public.delete_account(p_id uuid) returns void
language sql security definer as $$ delete from profiles where id = p_id $$;
-- app: supabase.rpc('delete_account', { p_id })
```

## Good

```sql
revoke execute on function public.delete_account(uuid) from public, anon;
grant execute on function public.delete_account(uuid) to authenticated;
-- and check auth.uid() = p_id inside the body
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG004 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG004 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG004": "off" }` in the config.
