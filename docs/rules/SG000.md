# SG000 - ScannerDiagnostics

**Severity:** info · **Layer:** config · **Auto-fix:** none

> Diagnostics from the scanner itself: unparsable files, suppressions without a reason, internal rule errors.

## Why it matters

Not a security rule. SG000 reports problems that reduce what the scanner could analyse: a file that failed to parse (ParseError), an edge-guard-disable comment without a reason (SuppressionWithoutReason), or a rule that crashed (InternalError).

## Bad

```ts
// edge-guard-disable-next-line SG001
```

## Good

```ts
// edge-guard-disable-next-line SG001 -- session only used to read the locale, never for authorization
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG000 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG000 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG000": "off" }` in the config.
