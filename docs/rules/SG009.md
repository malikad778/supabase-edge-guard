# SG009 - SharedClientSessionLeak

**Severity:** error · **Layer:** ts · **Auto-fix:** none

> A module-scope Supabase client has its session/auth mutated per request on the server.

## Why it matters

A client created at module scope is shared by every request handled by the same server instance. Calling auth.setSession() or setAuth() on it inside a handler makes the next request run with the previous user's credentials - a cross-user data leak that only shows up under concurrency.

## Bad

```ts
const supabase = createClient(url, anonKey);
export async function GET(req: Request) {
  await supabase.auth.setSession({ access_token, refresh_token });
}
```

## Good

```ts
export async function GET(req: Request) {
  const supabase = createClient(url, anonKey); // per-request client
  await supabase.auth.setSession({ access_token, refresh_token });
}
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG009 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG009 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG009": "off" }` in the config.
