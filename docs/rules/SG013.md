# SG013 - SecurityDefinerWithoutSearchPath

**Severity:** warning · **Layer:** sql · **Auto-fix:** unsafe

> SECURITY DEFINER function without SET search_path.

## Why it matters

A SECURITY DEFINER function resolves unqualified names using the caller's search_path. An attacker can create a same-named object in a schema they control and have the function run it with owner privileges (CVE-2018-1058 style). Pin search_path on every definer function.

## Bad

```sql
create function public.bump() returns void language sql security definer as $$ update counters set n = n + 1 $$;
```

## Good

```sql
create function public.bump() returns void language sql security definer set search_path = '' as $$ update public.counters set n = n + 1 $$;
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG013 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG013 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG013": "off" }` in the config.
