# SG012 - PolicyTrustsUserMetadata

**Severity:** error · **Layer:** sql · **Auto-fix:** none

> RLS policy reads user_metadata / raw_user_meta_data, which users can edit themselves.

## Why it matters

user_metadata is writable by the signed-in user through auth.updateUser(). A policy such as (auth.jwt() -> 'user_metadata' ->> 'role') = 'admin' lets any user make themselves admin. Authorization data belongs in app_metadata or a table only the server can write.

## Bad

```sql
create policy "admins" on public.secrets using ((auth.jwt() -> 'user_metadata' ->> 'role') = 'admin');
```

## Good

```sql
create policy "admins" on public.secrets using ((select auth.jwt() -> 'app_metadata' ->> 'role') = 'admin');
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG012 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG012 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG012": "off" }` in the config.
