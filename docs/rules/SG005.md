# SG005 - RlsPolicyAuthUidNotWrapped

**Severity:** warning · **Layer:** sql · **Auto-fix:** safe

> auth.uid()/jwt()/role()/email() in an RLS policy is not wrapped in (select ...).

## Why it matters

Calling auth.uid() directly in a policy makes Postgres evaluate it once per row. Wrapping it in (select auth.uid()) turns it into an initPlan that is evaluated once per query. On large tables this is the difference between milliseconds and timeouts, and it is the most common finding of the Supabase database linter.

## Bad

```sql
create policy "own rows" on public.notes using (user_id = auth.uid());
```

## Good

```sql
create policy "own rows" on public.notes using (user_id = (select auth.uid()));
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG005 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG005 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG005": "off" }` in the config.
