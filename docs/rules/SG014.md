# SG014 - ViewBypassesRls

**Severity:** warning · **Layer:** sql · **Auto-fix:** unsafe

> View over an RLS-protected table is not security_invoker, so it bypasses the table policies.

## Why it matters

Views run with the privileges of their owner (usually postgres), which bypasses RLS on the underlying tables. Exposing such a view through the API leaks rows the policies were meant to hide. Postgres 15 added WITH (security_invoker = true) to make the view respect the caller's RLS.

## Bad

```sql
create view public.my_orders as select * from public.orders;
```

## Good

```sql
create view public.my_orders with (security_invoker = true) as select * from public.orders;
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```

```

In SQL files use `-- edge-guard-disable-next-line SG014 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG014": "off" }` in the config.
