# SG008 - StorageWriteUnprotected

**Severity:** error · **Layer:** cross · **Auto-fix:** none

> Storage bucket written from the browser without an owner-scoped storage.objects policy (or public bucket writable by anon).

## Why it matters

Storage access is governed by RLS policies on storage.objects. A policy that only checks bucket_id lets any authenticated user overwrite or delete anyone's files; a public bucket with an anon write policy lets the whole internet upload.

## Bad

```sql
create policy "upload avatars" on storage.objects for insert to authenticated
  with check (bucket_id = 'avatars');
```

## Good

```sql
create policy "upload own avatars" on storage.objects for insert to authenticated
  with check (bucket_id = 'avatars' and (storage.foldername(name))[1] = (select auth.uid())::text);
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG008 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG008 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG008": "off" }` in the config.
