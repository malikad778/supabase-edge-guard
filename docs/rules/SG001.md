# SG001 - ServerAuthGetSessionSpoof

**Severity:** error · **Layer:** ts · **Auto-fix:** safe

> auth.getSession() used for authentication in server, edge or middleware code.

## Why it matters

getSession() reads the session straight from the cookie without asking the Auth server to verify it. An attacker can craft a cookie with any user id, so authorization decisions based on session.user are spoofable. Supabase documents this and recommends getUser() (verified) or getClaims() (verified JWT signature) on the server.

## Bad

```ts
const { data: { session } } = await supabase.auth.getSession();
if (!session) redirect('/login');
await db.update(session.user.id);
```

## Good

```ts
const { data: { user } } = await supabase.auth.getUser();
if (!user) redirect('/login');
await db.update(user.id);
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG001 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG001 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG001": "off" }` in the config.
