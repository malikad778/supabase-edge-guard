# SG010 - TableWithoutRls

**Severity:** error · **Layer:** sql · **Auto-fix:** safe

> Table in an exposed schema never has ROW LEVEL SECURITY enabled.

## Why it matters

Every table in the public schema is reachable through the auto-generated REST API with the anon key. Without RLS the table is fully readable and writable by anyone who knows your project URL. Forgetting ENABLE ROW LEVEL SECURITY on a new table is the single most common Supabase data leak.

## Bad

```sql
create table public.orders (id uuid primary key, user_id uuid, total numeric);
```

## Good

```sql
create table public.orders (id uuid primary key, user_id uuid, total numeric);
alter table public.orders enable row level security;
create policy "own orders" on public.orders using (user_id = (select auth.uid()));
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG010 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG010 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG010": "off" }` in the config.
