# SG006 - OverlyPermissivePolicy

**Severity:** error · **Layer:** sql · **Auto-fix:** none

> Policy that is effectively 'allow everyone': auth.uid() IS NULL OR ..., or USING (true) on writes.

## Why it matters

"auth.uid() IS NULL OR owner = auth.uid()" is true for every anonymous request, and USING (true) on UPDATE/DELETE/ALL lets anon or any user rewrite the table. Both pass casual review because the policy "exists", yet RLS no longer protects anything.

## Bad

```sql
create policy "anyone" on public.posts for update using (true);
create policy "mine" on public.notes using (auth.uid() is null or user_id = auth.uid());
```

## Good

```sql
create policy "owner updates" on public.posts for update to authenticated using (author_id = (select auth.uid()));
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG006 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG006 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG006": "off" }` in the config.
