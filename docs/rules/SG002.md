# SG002 - ServiceRoleWithoutAuthCheck

**Severity:** error · **Layer:** ts · **Auto-fix:** none

> service_role client used on user-controlled input or without verifying the caller first.

## Why it matters

The service_role key bypasses every RLS policy. When a server action or route handler uses it with an id taken from the request (or without calling auth.getUser() first), any caller can read or modify any row. This is the classic "IDOR via admin client" bug.

## Bad

```ts
const admin = createClient(url, process.env.SUPABASE_SERVICE_ROLE_KEY!);
export async function POST(req: Request) {
  const { id } = await req.json();
  await admin.from('orders').delete().eq('id', id);
}
```

## Good

```ts
const { data: { user } } = await supabase.auth.getUser();
if (!user) return new Response('unauthorized', { status: 401 });
await supabase.from('orders').delete().eq('id', id); // RLS enforces ownership
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG002 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG002 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG002": "off" }` in the config.
