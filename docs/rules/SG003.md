# SG003 - ServiceRoleInClientBundle

**Severity:** error · **Layer:** cross · **Auto-fix:** none

> service_role key referenced from code that is bundled for the browser.

## Why it matters

Anything reachable from a "use client" module (or any module in a Vite SPA) ends up in the public JavaScript bundle. Shipping the service_role key there hands every visitor a credential that bypasses all RLS. Leaked keys of this kind are routinely scraped within hours.

## Bad

```ts
'use client';
import { createClient } from '@supabase/supabase-js';
const supabase = createClient(url, process.env.NEXT_PUBLIC_SUPABASE_SERVICE_ROLE_KEY!);
```

## Good

```ts
'use client';
const supabase = createClient(url, process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!);
// service_role lives only in server-only modules
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG003 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG003 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG003": "off" }` in the config.
