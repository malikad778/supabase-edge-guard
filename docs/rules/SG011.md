# SG011 - RlsEnabledWithoutPolicies

**Severity:** info · **Layer:** sql · **Auto-fix:** none

> RLS is enabled but the table has no policies, so every client request is denied.

## Why it matters

With RLS on and zero policies the table is locked for anon and authenticated roles. That is safe, but often an unfinished migration: the app silently gets empty results or permission errors.

## Bad

```sql
alter table public.notes enable row level security;
-- no create policy statements
```

## Good

```sql
alter table public.notes enable row level security;
create policy "own notes" on public.notes using (user_id = (select auth.uid()));
```

## Suppressing

Only suppress after you have confirmed the finding is a false positive. A reason is mandatory; suppressions without one are ignored and reported as `SG000`.

```
// edge-guard-disable-next-line SG011 -- <why this is safe>
```

In SQL files use `-- edge-guard-disable-next-line SG011 -- <reason>`. Use `edge-guard-disable-file` to cover a whole file, or set `"rules": { "SG011": "off" }` in the config.
